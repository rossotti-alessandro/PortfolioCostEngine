> **One-liner**: Each person signs in with their own account via Microsoft 365 (OIDC) with MFA, or a local account with passkey, and gets analyst, senior, admin or auditor rights.

## Description

### Context

One env-seeded admin (PR #9). No way to tell who did what; no MFA; revoke means rotating the key.

### User Flow Impact

Sign in with Microsoft button; admin page lists users.

### Performance / Efficiency Impact

Server-side session lookup per request; negligible.

### Proposed Approach

1. ADR for OIDC (Authlib, BSD) and session store
2. User table per tenant, roles
3. Server-side sessions with idle timeout and revoke
4. Keep env admin as break-glass

### Risks & Follow-ups

Auth change: needs Ale's per-PR approval (rule 9). DB schema is a shared contract. Plan: "FeeLens: going live with client data" (project doc, 2026-11-12).

## Acceptance Criteria

- [ ] #1 A user of tenant A cannot read tenant B, and a revoked session is refused on the next request
- [ ] #2 Existing env admin sign-in keeps working as break-glass (regression guard)
