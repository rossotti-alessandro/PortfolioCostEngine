> **One-liner**: Find structured personal identifiers (IBAN, Swiss AHV/AVS number, card numbers, email, phone, labelled account and relationship numbers) in extracted text, locally, with no new dependency.

## Description

### Context

No component knows where personal data sits in a document. Every later privacy step (redaction, egress guard, log scrubbing, agentic checker) needs one detector to call.

### User Flow Impact

None directly. Later stories use it to redact exports and block outbound payloads.

### Performance / Efficiency Impact

Pure Python regex + checksum over page text; well under 1 ms per page.

### Proposed Approach

1. `pce/pii.py`: `Span` model (kind, start, end, text hash, confidence, rule) and `detect(text) -> list[Span]`
2. Rules: IBAN with mod-97, AHV/AVS 756 EAN-13 check digit, card numbers with Luhn, email, international phone, account/relationship/client numbers only next to a label (IT/DE/FR/EN)
3. `mask(text, spans)` returns text with `[IBAN_1]`-style tokens
4. Unit tests on SYNTHETIC strings, including false-positive guards (ISINs, amounts, dates)

### Risks & Follow-ups

Names and addresses need a model (SC-11.9). Rules must never flag ISINs, otherwise public lookups break. Plan: "FeeLens: going live with client data" (project doc, 2026-11-12).

## Acceptance Criteria

- [x] #1 `detect` finds every synthetic IBAN, AHV, card, email, phone and labelled account number in the test set, with checksums enforced (invalid check digits are not flagged)
- [x] #2 ISINs, amounts, percentages and dates in the same text are not flagged (regression guard)

## Implementation Notes

- Owned paths as declared: `backend/src/pce/pii.py`, `backend/tests/test_pii.py`.
- Check digits reuse python-stdnum (`iban`, `ch.ssn`, `luhn`), already a dependency; no new package.
- `Span` stores offsets and kind only, never the matched text, so spans can be logged.
- Account rule: a label (IT/DE/FR/EN) directly followed by a number with 5+ digits; dates, periods
  ("2025-2026"), two-decimal amounts and valid ISINs are excluded.
- `mask()` gives one token per distinct value (`[IBAN_1]`), ignoring spaces and separators.
- Sanity run over the 17 synthetic PDFs in `data/`: 3 hits, all true (synthetic dossier/portfolio numbers),
  no false positives.
