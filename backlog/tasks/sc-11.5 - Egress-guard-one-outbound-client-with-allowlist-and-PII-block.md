> **One-liner**: Every outbound HTTP call goes through one client that only reaches allowlisted hosts and refuses any payload where the detector finds personal data.

## Description

### Context

ADR 0004 says public lookups send ISINs only, but nothing enforces it in code.

### User Flow Impact

None, unless a call is blocked: then the analyst sees 'blocked: would send personal data'.

### Performance / Efficiency Impact

One `detect` pass per outbound payload; negligible.

### Proposed Approach

1. `pce/egress.py` wrapping httpx with host allowlist from settings
2. Payload scan with `detect`; block and log ids only
3. Test that refuses a payload with a synthetic IBAN and a non-allowlisted host

### Risks & Follow-ups

Privacy-relevant: needs Ale's per-PR approval under AGENTS.md rule 9. Plan: "FeeLens: going live with client data" (project doc, 2026-11-12).

## Acceptance Criteria

- [ ] #1 A request to a non-allowlisted host or with a synthetic IBAN in its body raises and sends nothing
- [ ] #2 An ISIN-only lookup to an allowlisted host passes (regression guard)
