> **One-liner**: The rule-based masker hides every bank identifier on a 100-page SYNTHETIC test set
> (IBANs wrapped or misread, account numbers repeated without their label, Swiss phones), and the set
> measures it.

## Description

### Context

`pce.pii` (SC-11.3) missed 30% of IBANs and 62% of account numbers on statement-shaped text. The fixes and
the measurement set were written in PR #48 (2026-11-13, under SC-11.9), which was closed because it
conflicted with the roles and activity log work. SC-11.9 itself (local model for names and addresses) stays
open.

### User Flow Impact

None visible: masking runs where data leaves the app.

### Performance / Efficiency Impact

No measurable impact (regex only).

### Proposed Approach

1. `pii.py`: IBAN across one line break, labelled IBAN with an OCR misread, Swiss 3-3-2-2 phones, account
   numbers with a leading dash, every repeat of a found value, year rows not taken for card numbers.
2. `tests/evaluation/pii_set.py`: 100 SYNTHETIC pages (IT/DE/FR/EN), 1'275 gold spans; test keeps the
   identifier recall at 100% and precision at 100%.
3. `docs/research/PII_MEASUREMENT.md`: results and what still needs a model.

### Risks & Follow-ups

Fixes were made after looking at the set, so 100% is an upper bound. Names, addresses, birth dates: SC-11.9.

## Acceptance Criteria

- [x] #1 On the SYNTHETIC set every IBAN, AHV, card, account, phone and email span is fully hidden (tested)
- [x] #2 ISINs, valor numbers, amounts, dates, fee rates and the bank's BIC stay visible: precision 100% (tested)

## Implementation Notes

Ported from PR #48 commits aa330d0 and 5fea9fd. Re-run: `cd backend && uv run python -m tests.evaluation.pii_set`.

## Outcome

- **Status**: completed. Identifiers 685/685 hidden, precision 670/670 (2026-11-25 re-run on main).
