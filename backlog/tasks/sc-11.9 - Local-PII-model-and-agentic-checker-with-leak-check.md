> **One-liner**: Add names, addresses and contextual personal data to the detector with a local GLiNER2-PII model (Apache-2.0) and a local language-model checker that can only add redactions or ask a human.

## Description

### Context

Rules (SC-11.3) cannot find names or addresses. The revalidation thread is adding a local language model.

### User Flow Impact

Uncertain spans show up as review points for the analyst.

### Performance / Efficiency Impact

GLiNER2-PII ~300M params on CPU: to measure per page; run only on exits.

### Proposed Approach

1. Optional extra with GLiNER2-PII, labels per firm
2. Checker prompt with page crop + neighbours; may only add spans or escalate
3. Leak check: rules + model rerun on output, canary values in tests
4. Score on a synthetic PII set

### Risks & Follow-ups

Model licence check before adding; local only (ADR 0004). Coordinate with 'Add agentic revalidation of extracted values'. Plan: "FeeLens: going live with client data" (project doc, 2026-11-12).

## Acceptance Criteria

- [ ] #1 On the synthetic PII set, recall for names and addresses is reported and every rule-found span stays redacted after the checker
- [ ] #2 The checker cannot remove a rule-found span (regression guard)
