> **One-liner**: An authorised user can erase one prospect (documents, extracted facts, reviews, proposals,
> reports, CRM link) on request, and the audit log keeps only that the deletion happened.

## Description

### Context

ADR 0004 promises "deletion removes originals and derived facts". On main there is no endpoint that deletes
a prospect or a document: `api.py` only replaces a document's facts on re-extraction. SC-11.6 covers
automatic deletion after the retention period, not deletion on demand. A prospect who declines, or asks for
erasure, cannot be served today. This blocks real client data (READINESS.md gate G5).

### User Flow Impact

Prospect page gets a "Delete prospect and all documents" action behind a typed confirmation, admin role only.

### Performance / Efficiency Impact

No measurable impact.

### Proposed Approach

1. `DELETE /api/prospects/{pid}`: tenant-scoped, admin role, CSRF; deletes rows of every child table and the
   stored files by SHA-256 when no other prospect of the same tenant references the same file.
2. Audit entry `prospect.deleted` with code and counts only (no names, no file names).
3. Test: after deletion no row with that `prospect_id` exists in any table, the file is gone, another tenant's
   prospect with the same file is untouched, and a non-admin gets 403.
4. Frontend action with typed confirmation (prospect code).

### Risks & Follow-ups

Backups still hold the data until they rotate: SC-11.6 must document backup expiry. Touches the schema
(shared contract): coordinate with SC-11.2 and SC-11.8.

## Acceptance Criteria

- [x] #1 Deleting a prospect leaves no row or stored file for it; the audit log keeps one entry without personal data
- [x] #2 Cross-tenant and non-admin deletion return 403/404 and delete nothing (tested)

## Implementation Notes

Owned paths: backend/src/pce/erasure.py, api.py (DELETE route), tests/test_deletion.py, frontend Prospects.tsx.

## Outcome

DELETE /api/prospects/{id}, admins only, typed prospect code and a reason from a fixed list. Deletes documents, stored files no other prospect uses, facts, reviews, proposals, approvals, requests and earlier audit entries; unlinks or deletes the CRM contact; leaves one prospect.erased entry with counts only. Erase dialog on the Prospects list. Tests: tests/test_deletion.py (2).
